# Vela M5 — GitHub 私有仓库同步收藏夹：可行性研究与设计

- 日期：2026-09-08
- 结论：**可行，且建议做**。自研浏览器可以直接在 chrome 层实现同步引擎（无需扩展、无需自建服务器），GitHub 私有仓库作为存储后端，配合细粒度 PAT + 可选客户端加密，隐私与成本都可控。

## 1. 可行性依据

| 要素 | 结论 |
|---|---|
| 存储 | 私有仓库单文件（`vela/bookmarks.json`），GitHub Contents API 读/写（PUT 需带文件 SHA 做乐观锁）；或 Gist API（更简单，但 secret gist 有链接即可见，需配加密） |
| 鉴权 | Fine-grained PAT：只授权这一个仓库的 Contents 读写，权限最小化；吊销即时生效 |
| 网络 | chrome 层 `fetch` 直接可用（特权上下文无跨域限制）；限流 5000 次/时，同步场景绰绰有余 |
| 收藏数据源 | `PlacesUtils.bookmarks` 观察者（esr153 原生 API）：增/删/改/移动全事件，防抖 5s 推送 |
| 写入 | `PlacesUtils.bookmarks.insert/remove/move` 回放远端变更 |
| 加密（可选但推荐） | WebCrypto AES-GCM，用户口令派生密钥，**密文上库**——GitHub 侧只见密文，token 泄露也不泄收藏 |
| 冲突 | SHA 不匹配（远端已变）→ 拉取 → 按 URL 键合并（新增并集、删除用墓碑、同条目改者胜）→ 重试 PUT |

## 2. 中国大陆现实约束（诚实声明）

github.com 在大陆访问不稳定——同步会失败但**不丢数据**（本地 Places 始终是主数据源，GitHub 只是副本）。缓解：失败静默重试 + 状态指示；架构预留自定义 endpoint（可指向镜像/代理，或后续支持 Gitee 同源协议）。

## 3. 分期实现

- **M5a（核心，约 300-400 行 JS 模块 + 设置 UI）**：设置页"同步"分区（开关/PAT/仓库名/立即同步/上次同步时间/状态）；启动拉取 + 变更防抖推送；明文 JSON；LWW+SHA 重试。
- **M5b**：墓碑删除合并、多设备冲突合并完善、错误呈现。
- **M5c**：口令加密（AES-GCM）、Gist 后端可选、自定义 endpoint。

## 4. 安全边界

- PAT 存 Firefox Login Manager（主密码/系统钥匙串加密），不明文落盘。
- 加密开启后：服务器（GitHub）与网络中间人只见密文；口令不离开本机。
- 同步只覆盖"收藏夹"目录树；不碰历史/密码（后续可扩展，风险面分开评估）。

## 5. 决策点（实现前确认）

1. 后端选型：私有仓库文件（推荐，可版本化/可回滚）vs Gist（更简单）。
2. 是否首版就上加密（多一道口令输入，换取"GitHub 也看不到收藏"）。
3. PAT 引导流程：设置页内嵌 GitHub 文档链接 + 一键校验按钮。
